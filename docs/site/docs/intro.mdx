httpp is an HTTP client and server for Python and C++, built from one core. The server needs no separate process and the library needs no system packages.

The code on every page follows the language you pick in the top bar. Your choice is remembered, and `?lang=cpp` or `?lang=python` in a link preselects it. Where the two APIs differ, the page says so in text, and its last section, "API at a glance", lists the calls of the language you picked.

## Where to start

1. [Install](install.mdx) the Python package or build the C++ library.
2. [Answer a GET request](server/get-route.mdx) with a route that takes a path parameter.
3. Read what came in: [request data](server/request-data.mdx). Shape what goes out: [responses](server/responses.mdx).
4. Answer failures: [handle errors](server/errors.mdx). Show your routes to others: [document the API with Swagger UI](server/swagger.mdx).
5. Serve files: [send one](server/send-file.mdx), [serve a folder](server/serve-directory.mdx) or [browse files](server/file-browser.mdx).
6. Run code around every request with [hooks](server/hooks.mdx).
7. Mount, secure and stop the server: [the server handle](server/server-handle.mdx).
8. Call a server: [GET requests](client/get-request.mdx) and [requests with a body](client/post-request.mdx).
9. Save a file: [download](client/download.mdx), with a checksum, resume and no blocking.
10. Send a file or a form: [upload](client/upload.mdx), read from disk while it is sent.
11. Try a request from the terminal with [`httpp curl`](client/curl-command.mdx).
12. See how fast it is: [benchmarks](benchmarks.mdx).

## What is not here yet

These areas exist in the library and are documented only in the project README for now: routers, middleware, streaming responses (a file is covered in [send a file](server/send-file.mdx)), async handlers, WebSocket, sessions, running the server with `httpp run` (workers, reload, graceful shutdown), the client's timeouts, redirects, retries and proxies, and testing your app.
