<Only lang="cpp">

In C++, `httpp::server` is a **handle**. Copying it does not make a second server: you get another handle to the same one, with the same routes, settings and sockets. Python's `Server` is an ordinary object and works as it always did.

</Only>

<Only lang="python">

Python's `Server` is an ordinary object: `b = a` gives two names for one server, as it does for any Python object, and there is nothing to learn about copies. C++ has a handle type with rules of its own; switch to C++ in the top bar to read them. The examples below are the same ones in both languages.

</Only>

## Mount a folder and serve it over TLS

<Only lang="cpp">

```cpp
auto srv = httpp::directory("public").show_hidden(false)
               .mount(httpp::server(), "/")
               .tls("cert.pem", "key.pem");
srv.listen("0.0.0.0", 8443);
```

`mount` takes the server by value and gives it back, so a temporary works, and a `server` you already have sees what was mounted:

```cpp
httpp::server app;
httpp::directory("public").mount(app, "/static");   // `app` now serves /static
```

</Only>

<Only lang="python">

```python
app = httpp.Server()
httpp.Directory("public").show_hidden(False).mount(app, "/")
app.tls("cert.pem", "key.pem")
app.listen("0.0.0.0", 8443)
```

`Directory.mount(app, base)` changes the server you give it and returns nothing, so a server that is already in use sees what was mounted:

```python
app = httpp.Server()
httpp.Directory("public").mount(app, "/static")   # `app` now serves /static
```

</Only>

## What sharing means

<Only lang="python">

Nothing beyond what any Python object does: two names for a `Server` are the same server. There are no handles, so none of the rules for copies in C++ apply.

</Only>

<Only lang="cpp">

- **Copies share one server and its configuration.** Mounting or configuring through any handle changes all of them. `a.same_as(b)` tells whether two handles are the same server (their addresses differ).
- **The server closes when the last handle is destroyed**, or when you call `stop()` or `shutdown()`. It is no longer "when the original goes out of scope". A thread inside `listen()` holds a handle of its own, so the server lives while it runs.
- **Configure from one thread, before listening.** Registering routes through two handles at the same time is not supported, as it was not for one server.
- A moved-from handle has no server; assign to it or destroy it.

</Only>

## Stopping from a handler

<Only lang="cpp">

A handler that must stop the server captures `srv.stopper()`, **never a `server`**. A handler that holds a `server` makes a cycle (the server keeps the handler, the handler keeps the server) and the server is never freed.

```cpp
httpp::server srv;
srv.get("/quit", [stop = srv.stopper()](const httpp::server_request&, httpp::response& res) {
    stop.shutdown(std::chrono::seconds(2));
    res.body = "bye";
});
```

A `server_stopper` is a copyable weak handle with `stop()`, `shutdown(grace)` and `alive()`. It does not keep the server alive; once the server is gone, `stop()` and `shutdown()` do nothing.

</Only>

<Only lang="python">

A handler can call the methods of the server it belongs to. There is no stopper to capture, because there is no handle and no cycle to be careful about:

```python
app = httpp.Server()

@app.get("/quit")
def quit_server():
    app.shutdown(2)   # refuse new connections, let requests in progress finish, give up after 2 seconds
    return "bye"
```

`shutdown(grace)` takes the grace period in seconds (default `10`) and makes `listen()` return when it is done; it does nothing when the server is not listening. `stop()` is the immediate one.

</Only>

## Chaining on a temporary

<Only lang="python">

`Directory.mount(app, base)` returns nothing, so write the statements one after another, as in the first example. `Server.tls(...)` returns the server, so it can end a chain: `httpp.Server().tls("cert.pem", "key.pem")`.

</Only>

<Only lang="cpp">

Write `auto srv = chain...;`. A chain on a temporary returns a handle, not a reference into the temporary, so this is safe:

```cpp
auto srv = httpp::directory(".").mount(httpp::server(), "/").tls("cert.pem", "key.pem");
```

and a reference to the temporary does not compile: `auto& r = httpp::server().tls(...)` is an error, where it would have dangled at the end of the statement.

</Only>
