A handler can look at the method, the path, the query string, the headers and the body of the request it answers.

<Lang name="request_data" />

Send it a request:

```bash
httpp curl "http://127.0.0.1:8000/inspect?page=2" -H "X-Token: abc" -d "hello"
# POST /inspect
# page=2
# token=abc
# body=hello
```

The same program has a second route, `/upload`, which reads a form with a file in it. Send it one with `curl -F` (or with the [upload](../client/upload.mdx) example):

```bash
httpp curl -F title=shopping -F doc=@notes.txt http://127.0.0.1:8000/upload
# title=shopping
# name=notes.txt
# type=text/plain
# size=18
```

## What the code does

<Only lang="python">

The handler asks for `request` by name and gets an object with these attributes: `method`, `path`, `query`, `headers`, `cookies`, `path_params`, and the body as `body` (bytes), `text` (decoded) or `json()`. Header names in `headers` are lower-case, so you write `request.headers.get("x-token")`. For repeated headers or query names the first value wins.

</Only>

<Only lang="cpp">

The handler receives a `const httpp::server_request&`. `method`, `path` and `body` are plain `std::string` members. For the rest use the accessors: `query_param(name)`, `header(name)`, `path_param(name)` and `cookie(name)`. Each returns an empty string when the value is absent, and `header` ignores the case of the name. The raw lists are there too: `query`, `headers` and `path_params` hold name and value pairs in the order they arrived.

</Only>

`request.form()` (Python) and `req.form()` (C++) decode a `multipart/form-data` or urlencoded body. A text field is `form.field(name)` and a file is `form.file(name)`, which has `filename` (as sent, without any folder), `content_type` and the bytes. The whole body is held in memory while it is read, so the server limits its size (`max_body`, 100 MiB by default); the client side sends a file from disk without that cost, see [upload](../client/upload.mdx).
