`FileBrowser` (`httpp::file_browser` in C++) adds a page where people can look through a folder, search it, sort it and download files. It is read-only: no route accepts a body, so nothing can be uploaded, renamed or deleted. The page is one self-contained HTML document that comes with the library, so it needs no files of yours and no internet.

<Lang name="file_browser" />

With a `shared` folder next to the program, open `http://127.0.0.1:8000/files/` in a browser. The same data is there for programs:

```bash
curl "http://127.0.0.1:8000/files/api/list?path=/"
# {"path":"/","entries":[{"name":"a.txt","type":"file","size":5,"mtime":...},{"name":"sub","type":"dir",...}],"truncated":false,"limit":5000}
curl http://127.0.0.1:8000/files/raw/a.txt
# alpha
```

## What it serves

| Request | Answer |
|---|---|
| `GET /files` | the browser page |
| `GET /files/api/list?path=/sub` | the entries of one folder as JSON |
| `GET /files/raw/<path>` | the file itself; `Range` and `HEAD` work |

A file that could run code in the page's own origin (html, svg, xml, scripts and files of an unknown type) is always sent as a download, and `?download=1` makes any file a download.

<Only lang="cpp">

The header is `httpp/file_browser.hpp`. It is not part of `httpp.h`, so include it yourself, as the example does.

</Only>

## What it keeps out

The folder you give is a ceiling. `..` segments, backslashes, NUL bytes, absolute paths and symlinks that lead out of it are refused, and a missing path, a hidden path and a path outside the folder all get the same `404`, so an answer never tells which of them it was. Names that start with a dot are not listed and answer `404` unless you set `show_hidden`.

A file that could run code in the page's origin (html, svg, xml, js, a type httpp does not know) is never shown: its preview says so and "Open raw" downloads it. That is **safe mode**, and it is the default.

`set_safe_mode(false)` (Python `safe_mode=False`, `httpp browse --unsafe`) lets **html and svg only** be shown. "Open raw" renders them in the tab it opens, and the dialog shows an svg as an image (an html file stays text there, as before). Both are sent with `Content-Security-Policy: sandbox; default-src 'none'; ...`, so no script runs, nothing is fetched from another origin (images, styles and fonts of the same server still load), forms are blocked and the page has an opaque origin: it cannot reach the browser or the viewer's session. xml, js and unknown types stay downloads, and `?download=1` still forces a download.

The browser has **no login of its own**. The `before` hook of the server runs first, so that is the place to ask for a key or a session: see [hooks](hooks.mdx).

## Settings

Every setting is a method that returns the browser, so they chain, and the same names work in both languages. A bad value is refused where you set it and leaves the browser as it was.

| Setting | Default | Meaning |
|---|---|---|
| `set_title(text)` | `"Files"` | page header and tab title (escaped, any text is safe) |
| `set_theme(theme)` | `system` | `Theme.SYSTEM` follows the system, or `Theme.LIGHT` / `Theme.DARK`; the viewer can still switch |
| `set_accent("#rrggbb")` | empty | accent colour, empty for the default |
| `set_search(bool)` | `true` | show the filter box (it filters the open folder in the browser) |
| `set_show_hidden(bool)` | `false` | list and serve names that start with a dot |
| `set_max_entries(count)` | `5000` | a larger folder is cut at this many and flagged `"truncated"`; must be above 0 |
| `set_view(view)` | `list` | first view, `View.LIST` or `View.GRID` |
| `set_sort(key)` | `name` | first sort, `Sort.NAME`, `Sort.SIZE` or `Sort.DATE` |
| `set_safe_mode(bool)` | `true` | `true`: html, svg, xml, js and unknown types are only downloaded. `false`: html and svg are rendered (see below) |

In Python the enums are `httpp.FileBrowser.Theme`, `.View` and `.Sort`; in C++ they are `httpp::file_browser::theme_mode`, `view_mode` and `sort_key`. Python also takes the settings as keyword arguments: `httpp.FileBrowser("shared", title="Team files", view=httpp.FileBrowser.View.GRID)`.

A bad `base` (it must start with `/`) and a folder that does not exist or is the root of the file system are errors when you call `mount`: `ValueError` in Python, `std::invalid_argument` in C++.

## Where the two differ

| | Python | C++ |
|---|---|---|
| Mount | `httpp.FileBrowser(root).set_title(...).mount(app, base)` | `httpp::file_browser(root).set_title(...).mount(app, base)` |
| Settings | methods, or keyword arguments | methods |
| Enums | `FileBrowser.Theme`, `.View`, `.Sort` | `theme_mode`, `view_mode`, `sort_key` |
| Header | nothing to include | `httpp/file_browser.hpp` |
| Bad setup | `ValueError` | `std::invalid_argument` |
