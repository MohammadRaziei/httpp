A route ties a path to a function. When a `GET` request matches the path, the function runs and its result is sent back.

<Lang name="get_route" />

Run it, then ask for the route:

```bash
httpp curl http://127.0.0.1:8000/hello/world
# hello world
```

## What the code does

The path `/hello/` followed by a name matches any value in that position and hands it to your function as `name`.

<Only lang="python">

The name is written `{name}`. It arrives as an argument with that name. The function returns a `str`, which is sent as `200` with `text/plain; charset=utf-8`. Annotate the argument as `int` or `float` and httpp converts it for you.

`listen` sits under `if __name__ == "__main__":` so the file works both ways: `python get_route.py` serves on the host and port you wrote, and `httpp py run get_route:app` imports the file and picks host, port and workers itself. Without the guard `httpp py run` still works, but it skips your `listen` call and prints a warning.

</Only>

<Only lang="cpp">

The name is written `{name}`. The handler gets a `const httpp::server_request&` and fills in an `httpp::response&`. Read the value with `req.path_param("name")`, which returns a `std::string`, or `req.path_param<int>("name")` to get it as a number. Setting `res.body` is enough: a response whose status was never set is sent as `200`.

</Only>

`listen` blocks until the server is stopped.

## Typed parameters

Both languages use the same syntax, parsed by the same code. Add a type after a colon and the route only matches when the segment fits:

<Grid
  head={["Pattern", "Matches", "Does not match"]}
  rows={[
    ["`/users/{id}`", "any non-empty segment", "an empty one"],
    ["`/users/{id:int}`", "`42`, `-5`", "`abc`, `4.5`"],
    ["`/prices/{p:float}`", "`3`, `-3.5`", "`abc`, `1e5`"],
  ]}
/>

A segment that does not fit means the route does not match, so the request goes on to the next route that fits, or gets a `404`. A parameter is always a whole segment, and a malformed pattern (`:id`, `<id>`, `{id`, `a{id}`, an unknown type) is an error when the route is registered.
